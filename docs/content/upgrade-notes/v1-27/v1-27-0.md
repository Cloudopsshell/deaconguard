Released 2026-11-01. Everything in the release: [changelog](https://github.com/Cloudopsshell/deaconguard/blob/main/CHANGELOG.md#1270---2026-11-01). How to upgrade: [Upgrade](../../installation/upgrade.md).

## What's new

- **Live detection.** Between scans, the agent watches its machine, its containers and Kubernetes nodes as attacks happen: programs started from temporary folders or memory, shells started by web servers and databases, crypto miners, downloaded scripts piped into a shell, and changes to accounts, sudo rules, SSH keys, scheduled jobs and services. Alerts arrive within seconds on each host's new **Runtime** tab. See [Live detection](../../usage/live-detection.md).
- **Runtime alerts** and **Live detection stopped** notifications, for the channels that tick them.

## Before you upgrade

**Back up: database schema 32.** Hosts get live detection's settings, status and alerts, so 1.26 and earlier can't open the database afterwards. [Back up](../../usage/backup-and-restore.md#back-up) first.

## After you upgrade

1. **Upgrade the agents to 1.27.0.** Live detection starts on its own on machines with Linux 5.8 or later; older agents show **Agent too old** in the Hosts list's new **Live detection** column. The **Agents** page lists the agents to upgrade.
2. **Check it runs:** the dashboard's **Live detection** card says how many hosts are watched and why any other isn't. On a host's **Runtime** tab, **Send a test alert** proves the whole chain within about 20 seconds.
3. To be told about alerts, and when detection stops, tick **Runtime alerts** and **Live detection stopped** on a [notification channel](../../usage/notifications.md#events).

To keep it off on a host, an admin clicks **Turn off** on its Runtime tab.

## Kubernetes (Helm and Kustomize)

The node agent needs two more capabilities, `BPF` and `PERFMON`, which the 1.27.0 chart and Kustomize base add: upgrade them as on [Upgrade](../../installation/upgrade.md#helm), as well as the image. A node agent upgraded without them runs, scans as before, and shows live detection as **Not supported**, saying it isn't allowed to load programs into the kernel. If you keep your own copy of the DaemonSet, add `BPF` and `PERFMON` to its `capabilities.add`. The cluster agent doesn't need them: it doesn't watch a machine.

## Install script and packages

Nothing else to do: the agent runs as root.

## Docker Compose

If you run the Compose file's agent (`--profile agent`), use the 1.27.0 Compose file, whose agent has the `BPF` and `PERFMON` capabilities.

## Known issues

- Alerts name the program but not yet its container or pod.
- An agent watches the kernel it runs on: two agents on one machine, such as one installed with the install script and one in a container, each report the same events.
