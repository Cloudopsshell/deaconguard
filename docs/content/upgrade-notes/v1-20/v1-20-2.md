Released 2026-10-31. Everything in the release: [changelog](https://github.com/Cloudopsshell/deaconguard/blob/main/CHANGELOG.md#1202---2026-10-31). How to upgrade: [Upgrade](../../installation/upgrade.md).

## What's new

- **One token for the chart's agents:** `enrollment.existingSecret` gives one token to the node agents and the cluster agent alike. See [One token for the agents](../../installation/kubernetes.md#2-one-token-for-the-agents).
- **Enroll a machine > Kubernetes** on the Agents page makes the right token for it: reusable, for the server's address inside the cluster, with the secret command and the values.
- Clearer help when an agent in Kubernetes can't enroll, in its log and in the chart's notes.

## Before you upgrade

Nothing to do. Values that set `agent.enrollment` or `cluster.enrollment` keep working: they take precedence over `enrollment`.

## Kubernetes (Helm and Kustomize)

- To move to one token: create a reusable token with **Enroll a machine** > **Kubernetes**, put it in a secret, set `enrollment.existingSecret` to it, and remove `existingSecret` from `agent.enrollment` and `cluster.enrollment`. Agents already enrolled keep their identity and don't use a token again.
- If the node agent and the cluster agent already share one secret, its token must be reusable; the notes after `helm upgrade` say so.
- Kustomize doesn't change.
