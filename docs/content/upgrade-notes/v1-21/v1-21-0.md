Released 2026-10-31. Everything in the release: [changelog](https://github.com/Cloudopsshell/deaconguard/blob/main/CHANGELOG.md#1210---2026-10-31). How to upgrade: [Upgrade](../../installation/upgrade.md).

## What's new

- **A Kubernetes cluster is one entry** on **Hosts** and **Agents**, with its nodes listed under it, and its page shows what it runs: namespaces, workloads, pods and containers, with the vulnerabilities, misconfigurations and malware in each, and its nodes. See [The cluster's page](../../usage/kubernetes.md#the-clusters-page).
- **Revoking a token can disconnect the machines it enrolled**, and they say why. See [Revoking a token](../../usage/agents.md#revoking-a-token).
- **Remove revoked tokens** clears them from the list.
- A refused token says why: revoked, expired, already used, or unknown.

## Before you upgrade

**Back up the server's database.** 1.21.0 moves it to schema 29: it records which token enrolled each agent, and which hosts are a cluster's nodes or were disconnected. An older server can't open it afterwards. See [Back up and restore](../../usage/backup-and-restore.md).

## Kubernetes (Helm and Kustomize)

- Upgrade as on [Upgrade](../../installation/upgrade.md#helm). The chart upgrades the cluster agent and the node agents with the server.
- **The cluster's page needs the 1.21.0 cluster agent**, which lists the cluster's nodes, namespaces and pods. Until it has scanned the cluster, the page shows the findings only. After upgrading, press **Scan now** on the cluster, or wait for its schedule.
- Node agents from 1.19.0 on already report what the page needs. Your node hosts move under their cluster after its first scan with the 1.21.0 cluster agent.
- **Revoking now offers to disconnect.** When you replace a cluster's token with a new one, untick **Also disconnect them**, or the nodes go offline until they enroll with the new token.

## Install script and packages

Nothing to do. Revoking a token now offers to disconnect the machines it enrolled; untick it to keep them, as before.

## Docker Compose

Nothing to do.

## Known issues

- Machines enrolled before 1.21.0 with a reusable token are tied to it only when no other reusable token could have enrolled them at the time. Those the server can't tie to a token aren't offered for disconnecting: remove their hosts to disconnect them.
