Released 2026-11-26. Everything in the release: [changelog](https://github.com/Cloudopsshell/deaconguard/blob/main/CHANGELOG.md#1360---2026-11-26). How to upgrade: [Upgrade](../../installation/upgrade.md).

## What's new

- **Live detection on Linux 4.18 to 5.7**: RHEL, Rocky Linux and AlmaLinux 8, Ubuntu 20.04 and Debian 10, with every alert newer kernels have. Until now those hosts showed **Not supported**. See [Where it runs](../../usage/live-detection.md#where-it-runs).
- **`agent.olderKernels`** in the Helm chart, for node agents on those kernels.
- **The Jenkins example is fixed**: both checks run when the first finds something, and the Warnings plugin tip works on a failed build. If you copied it, see [Jenkins](../../usage/ci-cd.md#jenkins).
- The GitHub action's Summary page reads better: the config check's paths are separated, and the note on a refused code scanning upload starts with a capital letter.

## Before you upgrade

Nothing to do. The database stays at schema 35, so a 1.33, 1.34 or 1.35 server can still open it.

## After you upgrade

**Upgrade the agents on hosts with Linux 4.18 to 5.7** to use live detection there; the server needs nothing. Hosts that showed **Not supported** with "older than 5.8" start live detection by themselves within 5 minutes of their agent's upgrade, if it's turned on for them. Hosts with Linux 5.8 or later run the same watchers as before.

## Kubernetes, install script, packages and Docker Compose

- **Install script and packages:** nothing else to do. The agent runs as root and has what it needs.
- **Helm:** on nodes with Linux 4.18 to 5.7, set `agent.olderKernels: true`, which gives the node agent `SYS_ADMIN` and `SYS_RESOURCE`: those kernels predate the `BPF` and `PERFMON` capabilities. Leave it off on newer nodes.
- **Kustomize and Docker Compose:** on such hosts, add `SYS_ADMIN` and `SYS_RESOURCE` to the agent's capabilities.
