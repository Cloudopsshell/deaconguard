Released 2026-10-30. Everything in the release: [changelog](https://github.com/Cloudopsshell/deaconguard/blob/main/CHANGELOG.md#1180---2026-10-30). How to upgrade: [Upgrade](../../installation/upgrade.md).

## What's new

- **Notifications for running containers:** a containers scan now sends **Known exploited vulnerabilities** and **New critical vulnerabilities** for what is new in the images running on a host. The digest counts them too. See [Notifications](../../usage/notifications.md#events).
- **Two new events:** **New configuration findings** (medium or worse) and **Scan results**, a summary of every scan, even a clean one. Existing channels don't get them until you tick them.
- **Host names:** show a host by a name of your own instead of its hostname, such as `ip-10-92-0-178` on Amazon EC2: **Rename** on its page, or `DEACONGUARD_NAME` when enrolling. See [Names](../../usage/agents.md#names).
- An agent running a long scan, such as an audit, is no longer reported offline in the middle of it.

## Before you upgrade

- **Back up** the server: 1.18.0 moves the database to schema 28 (a new column for host names), and an earlier release can't open it afterwards. See [Back up and restore](../../usage/backup-and-restore.md).
- Existing hosts keep their hostnames until you rename them; agents don't need upgrading for names.

## Kubernetes (Helm and Kustomize)

- Upgrade as on [Upgrade](../../installation/upgrade.md#helm). The chart's values don't change.

## Install script and packages

Nothing to do. To name a new agent's host, add `DEACONGUARD_NAME=…` before `sudo -E`.

## Docker Compose

Nothing to do.

## Known issues

Nothing to do.
