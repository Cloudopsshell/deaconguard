Released 2026-11-08. Everything in the release: [changelog](https://github.com/Cloudopsshell/deaconguard/blob/main/CHANGELOG.md#1330---2026-11-08). How to upgrade: [Upgrade](../../installation/upgrade.md).

## What's new

- **Live detection names the container:** alerts from containers have the container's name and image, and in Kubernetes its namespace and pod; the Runtime tab filters by them. See [Which container](../../usage/live-detection.md#which-container).
- **Live detection allowlist:** **Don't alert on this again** on an alert, or **Settings → Live detection allowlist**, skips expected alerts on a host, a cluster or all hosts, and counts them. See [Allowlist](../../usage/live-detection.md#allowlist).
- **Scheduled scans:** a time skipped when the clocks go forward runs an hour later in every time zone; west of UTC it ran an hour early.

## Before you upgrade

**Back up the database.** The server moves it to schema 35 when it starts: alerts get their container, and the allowlist gets its tables. Nothing is removed, but an older server can't open the database afterwards.

## After you upgrade

**Upgrade the agents to 1.33.0** where live detection is on: they name the container of each alert, and skip allowlisted alerts before the 30-alerts-a-minute limit. Older agents keep working as before; the server skips their allowlisted alerts. Nothing else changes: live detection stays off where it's off, and the allowlist starts empty.

## Kubernetes, install script, packages and Docker Compose

Nothing else to do. In Kubernetes the node agent finds pods with the node's own `crictl`, through the node's root it already mounts.
