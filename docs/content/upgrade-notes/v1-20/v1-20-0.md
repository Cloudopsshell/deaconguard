Released 2026-10-31. Everything in the release: [changelog](https://github.com/Cloudopsshell/deaconguard/blob/main/CHANGELOG.md#1200---2026-10-31). How to upgrade: [Upgrade](../../installation/upgrade.md).

## What's new

- **Running images of clusters:** each dashboard scan of a cluster also checks the images its pods run, on the server, as image scans do: no node agent needed. Each image with vulnerabilities to fix is a finding, notified as **New cluster findings** when critical or high. See [Running images](../../usage/kubernetes.md#running-images).
- It stays light: each build is read from its registry once a day, at most 10 new images per scan, one at a time.

## Before you upgrade

- **The server now contacts the registries of the images your clusters run**, such as Docker Hub and GHCR, when it scans a cluster. If it can't reach them, the scan still completes and its notes list the images that couldn't be read. For private registries, add a login on the **Images** page.
- **Upgrade the cluster agent** as well as the server, so the server checks the exact builds the pods run. With an older cluster agent, the server checks each image's tag as it is now, and the scan says so.
- The first scans after the upgrade may report images with vulnerabilities as new cluster findings, and send them to channels with **New cluster findings**: they were running before, but weren't checked.
- The database doesn't change.

## Kubernetes (Helm and Kustomize)

- Upgrade as on [Upgrade](../../installation/upgrade.md#helm), the release with the cluster agent included. The chart's values don't change.
